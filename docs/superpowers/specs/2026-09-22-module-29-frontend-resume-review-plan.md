## 1. 模块职责与边界

### 1.1 职责

| 子职责 | 内容 | PRD |
|---|---|---|
| HR 侧入口 | 面试详情页「候选人简历」面板动作区加「评估匹配度」按钮 | §4.15 |
| 候选人侧入口 | 「我的简历」页「用于面试」每一行加「评估匹配度」按钮 | §4.15、§4.13 |
| 结果展示 | 两端统一用**弹窗**展示：分数（若有）+ 结论 + 亮点 + 差距 | §4.15 |
| 档位适配 | 候选人拿不到分数时**整块隐藏分数区** | §4.15、§9 |
| 前置引导 | 未关联简历时按钮禁用并给出 hover 提示 | §4.15、§7 |
| 忙态与降级 | 调用期间按钮禁用；失败提示可重试 | §7 |

### 1.2 边界（明确不做）

| 不做 | 理由 |
|---|---|
| **在候选人「面试详情（答题页）」加入口** | 简历关联与查看的入口**按既有决定在「我的简历」页**（F9/F10 的既定结论）。答题页是另一条链路，把评估放进去会让同一件事有两个入口 |
| **在 HR 的「面试列表」加入口** | 评估需要先看简历，列表页没有简历上下文 |
| **缓存 / 本地保存评估结果** | PRD §4.15 明确「每次现算」。前端持久化一份会让「刷新即无」这个约定失效，且会与后端产生两份可能不一致的结果 |
| **自动评估（进页面就跑）** | 每次调用都烧一次 AI。**必须是用户点击触发** |
| **分数可视化（进度条 / 环形图 / 雷达图）** | 无图表库；雷达图是面试评估的图形（§4.5），简历评估 PRD 未要求图形 |
| **候选人侧展示档位说明**（「管理员未开放分数」之类） | 候选人不需要知道部署配了哪一档（module-28 §3.2）。**分数区直接不出现，不加任何解释性文案** |
| **多简历对比、评估历史** | PRD §1.3 / §4.15 非目标 |
| **后端与 e2e** | 属 module-27 / 28 / 30 |

## 3. 接口契约

### 3.1 共用组件 `components/resume-review.js`

| 导出 | 签名 | 说明 |
|---|---|---|
| `scoreBand(score)` | `-> { label, tone }` | 纯函数：分数 → 档位文案与样式类；`score === null` → `{ label: '', tone: '' }` |
| `openResumeReview({ interviewId, side, onDone? })` | 无返回 | 打开弹窗：显示忙态 → 调对应端点 → 渲染结果 |

**`scoreBand` 的档位（与后端结论档位对齐，module-27 §4.2）**

| 分数 | `label` | `tone` |
|---|---|---|
| `null` | `''` | `''` |
| ≥ 8.0 | `'重合度高'` | `'is-high'` |
| 6.5 – 8.0 | `'重合度较好'` | `'is-mid'` |
| 4.0 – 6.5 | `'部分重合'` | `'is-low'` |
| < 4.0 | `'重合较少'` | `'is-weak'` |

> ⚠️ **`scoreBand` 的文案只说「重合度」，不得出现「通过 / 不通过 / 推荐 / 不推荐」**：UI 上的每个字都受 §4.9 / §4.15 的去留判断红线约束。**后端已经守住了结论文案，前端不要在前端又贴一个判断标签把它破掉。**
>
> **边界用 6.5（`PASS_THRESHOLD` 同值）**：与后端档位一致。若后端改了档位边界，这里要同步——**注释写明「与 module-27 §4.2 的档位表保持一致」**。

**`openResumeReview` 的 `side` 取值**

| `side` | 端点 | 守卫 |
|---|---|---|
| `'hr'` | `POST /interviews/{id}/resume-review` | HR 登录态 |
| `'candidate'` | `POST /candidate/interviews/{id}/resume-review` | 候选人登录态 |

> `side` 由**调用方显式传入**，不让组件去猜当前是 HR 还是候选人端。两端的登录态按 key 分开存储（`hr.*` / `candidate.*`，§9），「猜」需要读 session，而组件不该依赖 session 的形状。

### 3.2 弹窗内容契约

| 区块 | HR 侧 | 候选人侧（`match_score` 非 null） | 候选人侧（`match_score` 为 null） |
|---|---|---|---|
| 分数区 | 显示 `match_score` + `scoreBand` 标签 | 同 HR | **整块不渲染** |
| 综合结论 | 显示 | 显示 | 显示 |
| 亮点 | 显示，逐条 | 显示 | 显示 |
| 差距 | 显示，逐条；**为空时显示「未发现明显差距」** | 同 HR | 同 HR |
| 页脚 | 「关闭」 | 「关闭」 | 「关闭」 |

| 要点 | 说明 |
|---|---|
| **分数为 null 时「整块不渲染」，不是渲染成空值** | 显示 `0`、`—`、`暂无` 都会让候选人以为「我得零分」或「系统坏了」。**脱敏的正确 UI 表现是「这件事不存在」** |
| **`gaps` 为空时给一句固定文案** | 空白区块看起来像渲染失败。后端允许 `gaps` 为空（module-27 §3），前端要把它显示得像一个结论 |
| **弹窗内不放「重新评估」按钮** | 每次评估都烧一次 AI，重复触发的入口应当收敛到页面上的那一个按钮（关掉再点），而不是在弹窗里给一个容易连点的按钮 |
| **弹窗不显示「不落库 / 实时计算」这类系统说明** | 属系统内部行为，不是给候选人看的信息 |

### 3.3 页面内的调用点

**HR 侧**（`interview-detail.js`，简历面板）

| 项 | 内容 |
|---|---|
| 位置 | 简历面板 `panelHead` 的动作数组，**紧挨「按简历补题」之后** |
| 按钮文案 | 「评估匹配度」 |
| 禁用条件 | `detail.resume_id == null`（**只看是否关联简历，不看面试状态**——评估不限状态，见 module-28 §1.2） |
| hover 提示 | 未关联时：`'该面试尚未关联简历'`（**与后端 409 文案逐字一致**，见 module-28 §6） |
| 结果 | 点击后弹出 `openResumeReview({ interviewId, side: 'hr' })` |

> ⚠️ **不要照抄「按简历补题」的 `canMatch` 判定**（`interview-detail.js:464` 那行是 `detail.status === 'ongoing' && detail.resume_id != null`）。评估**不需要** `ongoing`，照抄会让一大半面试的按钮是灰的。

**候选人侧**（`candidate-resumes.js`，「用于面试」的每一行）

| 项 | 内容 |
|---|---|
| 位置 | `used-row` 内，`candidateStateTag(interview)` 之后 |
| 按钮文案 | 「评估匹配度」 |
| 条件 | **始终可点**（能出现在这一行，就说明这份简历已关联到该面试；岗位无维度时由后端 409 兜底并原样提示） |
| 结果 | `openResumeReview({ interviewId: interview.id, side: 'candidate' })` |

> **候选人侧不需要前置禁用**：这一行只在已关联时存在（`usedBy(resume.id)`），因此「未关联简历」的 409 不可能触发。**岗位无维度**是唯一可能的 409，而它是**部署配置问题**，前端无法预知——让它原样报出来比猜一个禁用态更诚实。

## 4. 交互流程

```
点击「评估匹配度」
  → 按钮进入忙态（disabled + 文案「评估中…」）
  → 打开结果弹窗，先显示 loadingBlock('AI 正在评估简历与岗位的匹配度…')
  → api.post(端点)                          ← 无请求体
      成功：
        - 关闭 loading，渲染四区块（按 §3.2 的表决定是否渲染分数区）
      失败（502 / 409 / 403 …）：
        - 关闭 loading，弹窗内显示错误文案（error.message 原样）
        - 弹窗底部保留「关闭」，**不提供「重试」**（重试 = 关掉再点页面上的按钮）
  → 按钮复位（finally）
```

| 要点 | 说明 |
|---|---|
| **先开弹窗再请求，而不是请求完再开** | 评估要调 AI，可能数秒。先开弹窗放 loading 才能让用户看到「正在跑」，否则按钮转几秒像卡死 |
| **失败信息留在弹窗内，不是 toast** | 用户刚点的是这个按钮，结果就展示在这个弹窗里；用 toast 会让「弹窗是空的 + 角落一句话」同时出现 |
| **按钮复位放 `finally`** | 弹窗中途关闭（点遮罩/ESC）不能让按钮永久卡在「评估中…」 |
| **失败时不自动重试** | AI 失败是 502，自动重试会再烧一次调用且可能同样失败 |

## 5. 走查（假后端）改动

### 5.1 假处理器

两个 harness 各加一条：

| harness | 路由 | 假响应 |
|---|---|---|
| `interviews-harness.js`（HR） | `POST /interviews/:id/resume-review` | 200 + 四字段（`match_score` 非 null） |
| `resume-harness.js`（候选人） | `POST /candidate/interviews/:id/resume-review` | 200 + `match_score` 为 **null**（复现默认档的脱敏） |

> 假后端**两种响应都要能造**（分数有/无），因为「分数为 null 时隐藏分数区」这条是走查的重点断言。

### 5.2 走查断言

**HR 侧（`interviews-harness.js`）**

| # | 断言 |
|---|---|
| 1 | 简历面板有「评估匹配度」按钮 |
| 2 | `resume_id` 为 null 时按钮 `disabled`，且 `title` 为「该面试尚未关联简历」 |
| 3 | **`completed` 状态的面试，按钮仍可点**（防「照抄补题的 ongoing 判定」这个回归） |
| 4 | 点击后发出 `POST /interviews/:id/resume-review`，**且无请求体** |
| 5 | 返回后弹窗显示分数、结论、亮点、差距四个区块 |
| 6 | `gaps` 为空数组时显示「未发现明显差距」 |

**候选人侧（`resume-harness.js`）**

| # | 断言 |
|---|---|
| 7 | 「用于面试」每一行都有「评估匹配度」按钮 |
| 8 | 点击后发出 `POST /candidate/interviews/:id/resume-review` |
| 9 | **`match_score` 为 null 时，弹窗内不存在分数区**（按 class 断言节点不存在，**不是**断言文本为空） |
| 10 | **弹窗内不出现 `0`、`—`、`暂无` 这类占位** |
| 11 | 结论、亮点、差距三个区块**照常显示**（脱敏不能把非分数内容一起藏掉） |
| 12 | 后端返回 409 + 中文文案 → **弹窗内**显示该文案原文 |
| 13 | 关闭弹窗后按钮**不卡在「评估中…」** |

> **第 9 条必须断言「节点不存在」而不是「文本为空」**：文本为空与节点不存在在视觉上都是空白，但只有后者符合 module-28 §5.2 的脱敏意图。若实现是「渲染了一个空 span」，断言文本为空会通过，而候选人会在 DOM 里看到那个占位节点——**这条断言的价值就在于逼实现真的不渲染**。
>
> **第 12 条必须断言「在弹窗内」而非「某处有这句话」**：§4 的契约是错误留在弹窗里。

### 5.3 无头跑法

沿用既有方式：Node + 系统 Edge，**必须套 `timeout`**。两个 harness 各跑一次。
