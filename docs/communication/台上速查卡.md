## 演示顺序（记住这条链就够）

**HR**：登录 `admin`/`admin12345` → 岗位（填评估维度）→ 面试（选岗位，题目自动生成）→ 面试详情 → **生成邀请码，复制**
**候选人**：登录 → 激活（粘邀请码）→ 逐题作答 → 交卷 → 刷题 → 错题本 / 统计
**回 HR**（有时间才做）：开始评估（看流式）→ 报告 → 导出 DOCX

**顺手展示的新功能**：登录页切「手机号登录」→ 填 `13800138000` → 获取验证码。
> 验证码会直接显示在页面上（演示环境没接真实短信）。用它登录会被送到**候选人端**——因为新号码自动建的是候选人账号。

## 三个「学到了什么」（这是老师最听的）

1. **把「谁有权看到什么」写成可执行的判据，不是写在注释里。** 加了候选人角色后，老接口只查「登录了吗」，候选人就能调 HR 接口——权限必须是代码。
2. **做「能力提供方」的抽象，不依赖外部账号也能完整演示。** AI 和短信都先实现「模拟版」，所以没密钥、不联网也能跑通全部功能和全部测试。
3. **测试的价值在于「能证伪」。** 把修好的 bug 故意植回去 33 次，有几次断言全绿、最后是看截图才发现的——全绿不等于正确。
